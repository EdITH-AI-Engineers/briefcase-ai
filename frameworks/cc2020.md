# ACM/IEEE Computing Curricula 2020 (CC2020) — dispositions + CS2013 knowledge areas (paraphrased)

Source: **ACM / IEEE-CS / AAAI, *Computing Curricula 2020: Paradigms for Global Computing Education — Final Report*, 31 December 2020.**
Canonical URL: https://www.acm.org/binaries/content/assets/education/curricula-recommendations/cc2020.pdf

**Verification status (2026-04-23):** CC2020 is a meta-framework that *aggregates* the curriculum reports of seven computing programs (CS, SE, IS, IT, CE, CSEC, DS). It does **not** publish a unified `KA-*` code namespace; the knowledge-area codes used in this bundle (`KA-SDF`, `KA-AL`, `KA-OS`, …) come from **ACM/IEEE Computer Science Curricula 2013 (CS2013)**, which is one of CC2020's input reports. They are used here as a convenience citation namespace for foundational CS knowledge. Disposition *names* are verified verbatim against CC2020's 11-disposition list (cross-checked via the NSF-archived paper Sabin et al., "Dispositions in Computing Education," which reproduces CC2020's disposition table). Disposition *codes* (`DISP-*`) are this bundle's synthetic citation tokens — CC2020 itself refers to dispositions by name only.

## Knowledge-area codes (from CS2013, used as a convenience namespace)

Each code below is canonical to **CS2013** (the 2013 ACM/IEEE CS curriculum) and is folded into CC2020 Section 3 as one of the aggregated CS bodies of knowledge. Source for the 18 CS2013 KA codes: https://www.acm.org/education/cs2013 (CS2013 Final Report, 2013).

- **KA-AL** — Algorithms & Complexity. Algorithmic problem-solving, complexity analysis, algorithm design paradigms.
- **KA-AR** — Architecture & Organization. Digital logic, machine representations, memory hierarchy, performance, parallelism.
- **KA-CN** — Computational Science. Numerical/scientific computing, simulation, modeling.
- **KA-DS** — Discrete Structures. Logic, sets, counting, graphs, proof, probability foundations.
- **KA-GV** — Graphics & Visualization. Rendering, geometric modeling, visualization of data and processes.
- **KA-HCI** — Human-Computer Interaction. User-centered design, usability, accessibility, interaction paradigms.
- **KA-IAS** — Information Assurance & Security. Confidentiality, integrity, availability; threat modeling; secure design.
- **KA-IM** — Information Management. Data modeling, databases, data storage and retrieval, data integrity.
- **KA-IS** — Intelligent Systems. AI foundations, machine learning, knowledge representation, reasoning.
- **KA-NC** — Networking & Communication. Protocols, internetworking, wireless/mobile networking.
- **KA-OS** — Operating Systems. Processes, concurrency, scheduling, memory, file systems, virtualization.
- **KA-PBD** — Platform-Based Development. Mobile, web, cloud, embedded, game, robotic platforms.
- **KA-PD** — Parallel & Distributed Computing. Concurrency, parallel algorithms, distributed systems.
- **KA-PL** — Programming Languages. Language paradigms, type systems, runtime, compilation.
- **KA-SDF** — Software Development Fundamentals. Basic programming concepts, fundamental data structures, problem-solving.
- **KA-SE** — Software Engineering. Processes, requirements, architecture, design, quality assurance.
- **KA-SF** — Systems Fundamentals. Computational paradigms, cross-layer communication, state & state machines.
- **KA-SP** — Social Issues & Professional Practice. Professional ethics, legal, social, cultural dimensions of computing.

For specialized programs CC2020 also pulls in:
- **KA-DSA** (data science KAs from DS2021 / CC2020's DS subreport) — this bundle's alias for "Data Science & Analytics" coverage. https://dstf.acm.org/
- **KA-SEC** (cybersecurity KAs from CSEC2017) — this bundle's alias for cross-program cybersecurity coverage. https://cybered.acm.org/

These two aliases are synthetic bundle tokens; cite them only when a narrower CS2013 KA does not fit.

## CC2020 competency dimensions

CC2020 defines competency as `(knowledge + skills + dispositions) applied to a task`. The four `DIM-*` tokens below are this bundle's internal citation tokens for those parts of CC2020's competency model; CC2020 does not publish short codes for them.

- **DIM-K** — Knowledge dimension (what the student knows).
- **DIM-S** — Skills dimension (what the student can do).
- **DIM-D** — Dispositions dimension (how the student habitually acts).
- **DIM-T** — Task dimension (the authentic task the competency is demonstrated in).

## CC2020 dispositions (names verified)

CC2020 enumerates exactly **11 dispositions** by name. Names are verified verbatim; the `DISP-*` codes are this bundle's internal tokens (CC2020 does not assign codes to dispositions). Citation form: `[cc2020:DISP-<code>]`.

- **DISP-ADAPT** — Adaptable.
- **DISP-COLLAB** — Collaborative.
- **DISP-INV** — Inventive.
- **DISP-METIC** — Meticulous.
- **DISP-PASS** — Passionate.
- **DISP-PROAC** — Proactive.
- **DISP-PROF** — Professional.
- **DISP-PURP** — Purpose-driven.
- **DISP-RESP** — Responsible.
- **DISP-RSPV** — Responsive.
- **DISP-SELF** — Self-directed.

## How to cite

- For knowledge evidence: `[cc2020:KA-<CODE>]` (e.g. `[cc2020:KA-SDF]` for basic programming evidence). The KA codes originate in CS2013; we scope them under `cc2020:` as a single citation namespace for brevity.
- For disposition evidence: `[cc2020:DISP-<code>]` (e.g. `[cc2020:DISP-SELF]` for self-directed learning).
- For competency-dimension reasoning: `[cc2020:DIM-S]` or `[cc2020:DIM-D]`.

Prefer the most specific code that fits. If a piece of evidence touches multiple KAs, cite the one with the clearest connection.
